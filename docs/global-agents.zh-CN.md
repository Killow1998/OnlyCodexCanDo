# 主机全局 AGENTS 指南

[English](global-agents.md) | 中文

[最小核心](../templates/AGENTS.global.md)简短保留跨任务的判断、主动执行、授权边界与阶段记录。

## 核心行为

- 用第一性原理、奥卡姆剃刀和苏格拉底提问判断。
- 方案设计先检索成熟方案，比较复用与定制。影响架构或长期成本的取舍交给用户。
- 只修改授权范围，判断前先检查项目现状。
- 大改前说明范围，被纠正后检查同类问题；改变外部状态或难以撤销的动作需要对应授权。
- 测试可观察行为，证据足够即止。
- 重要阶段完成后，只在获准时提交，否则把结果保存在项目现有记录中。
- 任务结束后，清理临时产物和过期备份；是否保留不确定时，先询问用户。

核心不规定 Shell、操作系统、目录结构或固定测试仪式。

## 渐进式项目记录

阶段记录通过 [`organized-proj`](../skills/organized-proj/SKILL.md) 渐进加载。全局文件只保存触发条件；完整收尾流程留在 Skill 中，只有重要阶段完成时才读取。Skill 复用项目现有文档，小改动直接跳过。

配置全局文件时：

1. 检查 `organized-proj` 是否已全局安装。
2. 未安装时说明行为，并集中询问一次是否从本仓库安装。
3. 用户拒绝时不写入 Skill 引用，改用更新项目现有记录的通用规则。
4. 以后不再逐项目询问，也不自动安装项目文档目录。

详见[渐进式项目记录](workspace-continuous-documentation.zh-CN.md)。

## 按需开发规范

以下可选规范使用普通 Markdown 文件；配置全局入口时选择一次，无需逐项目安装，也不新增 Skill。

| 规范 | 读取时机 | 内容 |
| --- | --- | --- |
| [后端](../templates/optional/guides/backend.zh-CN.md) | 后端或编译型算法开发 | CMake/catkin/colcon 快速迭代、诊断日志限额、接口独立。 |
| [前端](../templates/optional/guides/frontend.zh-CN.md) | 设计或修改界面 | 信息层级、克制表达、交互与人的视觉验收。 |
| [审阅、提交与推送](../templates/optional/guides/git.zh-CN.md) | 审阅、提交或推送 | 用户主动要求的简化与审阅；普通 Git 操作不触发该流程。 |

只把选定语言的所选规范复制到实际全局 `AGENTS.md` 同目录下的 `guides/`，统一命名为 `backend.md`、`frontend.md`、`git.md`。仓库中文源文件带 `.zh-CN.md`，安装时改成上述名称；更新时保留本地修改。采用规范时先检查项目现有约定。

三份都选用时，全局文件只需增加一条读取入口：

```markdown
- 按任务读取本文件同目录下的 `guides/backend.md`（后端或算法）、`guides/frontend.md`（界面）或 `guides/git.md`（代码审阅、简化、提交或推送）。
```

只保留指向已安装规范的引用。这是要求 Agent 按条件主动读文件，不应假定 `@file.md` 自带条件加载功能；规范正文不复制进常驻核心。`templates/workspace/` 下的领域参考仍按需选用，避免重复安装内容重叠的 UI 规则。

规范明确要求快速迭代、有效且有上限的日志、独立接口和可用的用户流程。前端尺寸与时长作为实际预览的起点；文件长度用于检查职责，不强制按数字拆分。复用成熟检查工具和能省去重复劳动的短脚本。要求简化时主动改善结构，只要求审阅时给出意见；普通提交或推送不额外触发简化流程。

需要让日常编码偏好常驻时，可选用这一句：

> 遵循单一职责，采用可检索命名；注释仅补充代码未表达的信息。

## 简洁、坦诚地表达

选择此偏好时，替换原有报告规则，不另加同义条目：

> 中文表达借鉴 ASD-STE100：术语一致、主体明确、短句单义；结论先行，直陈事实与建议，删除冗余与自评。

保留能增加机制解释、因果辨析或有效分类的内容，把影响判断的不确定性写进具体陈述。避免逐行复述表格、揣测用户动机或刻意挑错。删掉一段后，事实、机制、条件和决策均未改变，就删除该段。

[ASD-STE100](https://www.asd-ste100.org/STE_faq.html) 是技术文档使用的受控英语，最初就是为了帮助非英语母语读者。中文协作借鉴其术语一致、主体明确和句意清楚，不照搬英语词表，也不宣称符合 STE 标准。

## 部署

先检查现有全局文件，删除过时或重复规则，写入前展示最终文本。只询问尚未决定的选项。备份旧文件后，一次写入选定核心与选项并读回验证。主机部署不授权修改项目、远程写入、提交或发布。

多主机比较时，分别比较核心和已选选项。无法访问的主机保持“未核实”；主机清单和私有路径不进入本仓库。
