## Continuous Project Documentation

Merge this section into the nearest applicable project `AGENTS.md` only after the workspace owner approves the documentation workflow. Reuse equivalent existing paths instead of copying these example names blindly.

- Before non-trivial work, read the canonical project-state document and the architecture, decision, verification, or worklog documents it routes to.
- Keep stable project rules and document routing in `AGENTS.md`. Do not store current task status, command transcripts, or machine-specific state here.
- After a meaningful phase or before context may be lost, update durable decisions, verified state, acceptance evidence, next safe action, and open risks in the existing canonical docs.
- Prefer one living project-state document over per-session handoffs. A temporary handoff must have a named consumer and a closure plan; after absorption, merge unique knowledge and remove the task-created temporary file.
- Reuse the project's existing worklog, changelog, architecture records, and naming conventions. Do not create parallel documentation systems.
- Before finishing, verify referenced paths, reconcile task-created notes, preserve unrelated user documents, and leave the workspace clean.
