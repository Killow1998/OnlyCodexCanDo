# 审阅、提交与推送

审阅、简化、提交或推送时读取。只要求审阅就给意见；要求简化才改代码。普通提交或推送直接执行最后一节。

## 主动要求的简化与审阅

保持对代码的全局最优调整，拒绝局部最优的改进，对代码进行消融实验，去除无意义的抽象、设计及测试，保持代码的可读性和可扩展性，使其模块化更加彻底，消除掉修改一个模块或者增加一个模块就必须全局进行调试的过程，目前不进行任何新功能的增加，只推进代码的优化，并且尽量减少单个文件的代码长度，推荐使用E2E的测试来确认功能完整性

## 提交与推送

- 核对暂存差异，排除任务外误改、凭据和临时产物。
- 按独立意图组织提交，遵循仓库惯例说明改了什么、为什么。
- 使用已授权的分支与远端。审阅本身不授权推送；强推或改写共享历史需要对应授权，原范围内已有授权继续有效。
