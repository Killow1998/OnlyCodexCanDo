# 审阅、提交与推送

审阅、简化、代码收尾、提交或推送时读取。“代码收尾”或“收尾推送”表示执行下节完整的代码简化与结构重构；“收尾推送”完成后再提交并推送。只要求审阅就给意见；普通提交或推送仅执行最后一节。

## 代码收尾、简化与审阅

现在进入代码收尾与全局重构阶段，请对当前代码库进行深度整洁与结构优化。本次调整严格锁定当前功能边界，不增加任何新功能，仅推进代码精简、解耦与架构优化。

在代码瘦身与反过度防御方面，请清理无意义的层层判空和偏执的边界检查。未与我确认具体风险、发生概率及代码代价前，严禁为了理论上更稳而自行增加针对极低概率并发或安全边界的复杂逻辑。外部输入仅在系统入口处做一次校验并转化为确定类型，内部传递时直接信任类型契约，移除内部各层的重复校验。同时对现有代码做消融实验，去除无意义的抽象与设计，只调用一次且不含独立复杂度的逻辑直接内联回调用处，能不用 try/catch 就不用，能一个函数写完就别拆。此外，请大刀阔斧删除大篇幅的过时注释、废弃代码段和冗余说明，让代码自解释，保持代码的最新鲜状态。

在架构解耦与全局调整方面，请拒绝局部最优的修补，从全局视角审视并调整数据流与控制流。保持代码的可读性和可扩展性，使其模块化更加彻底，厘清模块边界并消除隐式耦合，消除掉修改或新增一个模块就必须进行全局调试的过程。同时尽量减少单个文件的代码长度，按高内聚原则拆分职责过重的文件。测试层面请去除脆弱、无意义的细碎测试，推荐使用精简的 E2E 测试来确认核心功能完整性。

已安装 `simplify-codebase` 时，调用它完成本节的简化或审阅；否则直接按本节执行。

## 提交与推送

- 核对暂存差异，排除任务外误改、凭据和临时产物。
- 审阅本次涉及的 README：突出项目用途、核心能力和上手路径；将工作记录与维护指令放入对应文档，更新过时状态。
- 按独立意图组织提交，遵循仓库惯例说明改了什么、为什么。
- 使用已授权的分支与远端。审阅本身不授权推送；强推或改写共享历史需要对应授权，原范围内已有授权继续有效。
