# Backend and Algorithms

Read for backend services, compiled projects, or algorithm development.

## Fast iteration

- Treat edit-to-result time as a development metric. Reuse or complete a short verification entry that runs independently.
- Enable parallel builds and compiler caching supported by the project. Retain the actual build entry point and choose generators and caching tools such as ccache that it supports.
- Preserve build directories and caches. Build affected targets and dependencies incrementally. Use clean rebuilds for build-failure diagnosis or project-required release validation.
- Separate development and release configurations. Move one-time environment setup out of routine builds and correct flags that accidentally override development settings.
- Separate build targets and reduce unrelated recompilation caused by public headers. Use a separate build directory when changing the CMake generator.
- Move frequently changed parameters and experiment orchestration outside compilation. Provide offline replay or an independent algorithm entry that skips unrelated UI and service startup.
- Accelerate strategy experiments with scripts or existing interfaces. Keep one authoritative production algorithm and compare prototype and production results on the same inputs.
- For dedicated build or performance optimization, compare duration and result consistency on a representative task.

### CMake and ROS build entry points

| Project entry point | Focused build | Dependencies |
| --- | --- | --- |
| Plain CMake | `cmake --build <build-dir> --target <target>` | Uses the target dependencies in that build tree. |
| ROS 1 with catkin_tools | `catkin build <pkg>` | Includes the package and its workspace dependencies. Add `--no-deps` when dependencies are already built and unaffected. |
| ROS 2 with colcon | `colcon build --symlink-install --packages-up-to <pkg>` | Includes the package and its workspace dependencies. Use `colcon build --symlink-install --packages-select <pkg>` when dependencies are ready and unaffected. |

- Keep the workspace's existing catkin or colcon entry point, profile, and build/devel/install layout. Configure compiler caching through the tool's CMake argument interface. Select Ninja according to that tool's support.
- Include affected downstream packages in builds and verification after changing public headers, messages, services, or package interfaces.
- Confirm the underlying ROS environment (underlay) before building. For runtime verification, load the setup generated by this build and confirm that it resolves to the intended workspace artifacts.
- Enable `--symlink-install` by default for colcon to reduce copying and repeated installation for some script edits. C++ source changes still require compilation.

## Logs from the start

- Design logs alongside core behavior. Record key transitions, failure context, duration, and correlation identifiers.
- Use an existing or established logging library. Exclude credentials and summarize high-volume raw payloads.
- Use bounded asynchronous buffers, batched writes, and sampling or aggregation on high-frequency paths. Flush important errors promptly and count dropped events on buffer overflow.
- Read logs on events or at appropriate intervals.
- Default each service instance's local logs to **100 MB total (100,000,000 bytes)** across active and rotated files. Enforce the total across restarts through configurable rotation and retention.

## Interfaces and modules

- Connect frontend and backend only through explicit interfaces. Each owns its internal implementation and state. The backend owns authorization, validation, and business rules.
- Separate core logic from external adapters so modules can run and be verified independently.
- Specify requests, responses, errors, and compatibility. Share contracts or generated clients; keep callers independent of internal implementations and direct backend database access.
