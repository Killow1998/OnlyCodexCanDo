# 前端

设计或修改界面时读取。沿用已有设计体系；新界面以下述方案为起点，按实际效果调整。

## 信息与布局

- 围绕主要任务组织页面，用分组、间距和操作优先级表达结构。
- 删除重复的标签、口号、解释和装饰性眉题。保留必要指引、错误说明与无障碍名称。
- 文案采用目标用户熟悉的表达。选择控件放在用户实际决策的位置。

## 视觉与交互

- 复用设计变量与组件。新建 Web 配色优先采用 Radix Colors 等成熟语义色板。
- 字号先组织成 3～4 个层级，用字重、留白和颜色区分次要信息。正文以舒适阅读为准，小字号留给辅助信息。
- 统一光学对齐和间距，嵌套容器采用同心圆角。减少纯装饰的分隔符、阴影和彩色侧边条。
- 细分割线从 0.5～1px 试起，检查缩放后的可见性。
- 保留有助于理解状态变化的动效，过渡可从 250ms ease-out 起步。尊重减少动态效果的设置。
- 键盘焦点始终可见。列表导航到视口边缘时适度滚动，露出当前项与相邻内容。

## 行为与交付

- 通过约定接口访问后端。数据交互覆盖加载、空数据、失败和恢复状态。
- 启动预览并操作本次修改的交互，把实际界面交给用户判断视觉效果。无法预览时说明缺少的证据。
- 不写 UI 单元测试或文案、布局断言。重要业务交互用 E2E 或现有集成链路验证。
